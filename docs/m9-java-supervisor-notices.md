# M9 Java/GraalVM priority supervisor receipt — restricted parity

**Status:** Java M9 host-side CONTROL notice implementation stacked on M8 Java IR bridge [#17](https://github.com/atto-lang/atto-source.java/pull/17). This Java repository currently has a **restricted Python AOT source compiler**, not the general AttoLang Java canonical frontend.

M9 extends the proven `AttoM7CooperativeRuntime` scheduler with a host-owned `SupervisorNotice(kind, actorName, generation, supervisorId, messageId, faultCode, reason)` record, a separate supervisor notice queue, `poll_supervisor_notice()` and `await_supervisor_notice(timeoutMillis)`. Existing three-argument `spawn` remains supported with supervisor ID 0; a new four-argument overload accepts a caller-supplied supervisor identifier. Actor references still require object identity plus generation.

Each accepted mailbox DATA message gets a monotonically increasing per-incarnation numeric ID; a running or suspended receive retains that ID. STOP notices use message ID 0 and fault 0. A frame callback ArithmeticException (including generated checked arithmetic) leads to fault code 1 with the exact failed message ID; a general callback/host panic is code 101. Supervisor CONTROL delivery is recorded independently of DATA mailbox capacity and guarded by the runtime's original strict control-priority machinery. Repeated STOP coalesces; a subsequent PANIC is separately delivered. The existing conservation equation remains enforced at every snapshot.

The new `M9JavaSupervisorNoticeProbe` blocks the first guest-style frame before a checked ArithmeticException, saturates the accepted DATA mailbox, receives STOP while the frame is still running, releases that frame, then observes a single PANIC with exact supervisor/generation/message metadata and confirms one FAILED plus two ABANDONED accepted DATA turns. It also checks stale-ref and reincarnated actor fencing. This test is **an intentionally faulting Java frame callback**, not yet a language-level supervisor built from parsed arbitrary `.atto` source; the normal compiled M7 `.atto` counter and earlier callback isolation tests still execute in the same GraalVM Native Image suite.

**Required evidence:** exact source and carrier Git tree SHA, changed blob equality, all M7/M8 Python compiler tests, JVM execution, real GraalVM JDK25 Native Image built with `--no-fallback --gc=epsilon`, required M9 notice markers and byte-identical JVM/native stdout.
